Reports and DRSM

Each report is a plain text file, one per host, that DRSM reads in place of an SSH check.

Report format

The server saves the report as <host>_linux_report_agent.txt. It starts with KEY: value headers (VERSION, PLATFORM: linux, HOSTNAME, ETIME, DATETIME), followed by sections of name=value lines. Values with spaces are quoted.

VERSION: 1.1
PLATFORM: linux
HOSTNAME: web1.example.com
...
PERFORMANCE:
cpu_used_pct=7.4
load_15m=0.31
mem_available_mb=5120
END PERFORMANCE

drra report prints one without sending it.

Sections

SectionContents
SYSTEMRelease, kernel, vendor, model, serial number, virtualization, time zone
IP ADDRESSIPv4 and IPv6 addresses of the interfaces that are up
PERFORMANCECPU use (5 second sample), iowait, steal, load, memory, swap, processes, uptime
DISK USAGESize, use and inode use of every local file system
NETWORKTraffic, errors and drops of each interface
USERS, ACCOUNTSLogged in sessions, accounts with a login shell
SECURITYSELinux, firewalld or nftables, auditd, FIPS, sshd root and password login, automatic updates
FAILED SERVICESFailed systemd units
UPDATESPending package updates, last package install, restart needed for a new kernel
VULNERABILITIESSecurity advisories that apply, with severity, CVEs and fixed packages
COMPLIANCESCAP Security Guide profile score and failed rules (optional)
HOOKSOutput of the report hooks
UPLOADSState of the hook uploads
INSTALLED PACKAGESEvery package with version and install time

With scans on, the OpenSCAP HTML reports are saved next to it as <host>_linux_scap_report.html and <host>_linux_compliance_report.html.

DRSM

The DataReel System Monitor checks hosts with COLLECTOR=lra from their last report: DRSM never connects to them. They show on the dashboard next to the SSH monitored hosts, with the same alerts and trend graphs, and their advisories show on the Vulnerabilities page. DRSM releases after 1.33 include the Linux agent plugins; for DRSM 1.33 and earlier, drsm/install.sh in the agent source code copies them in (dry run, then --apply).

Set up DRSM

  1. Set LRA_REPORTS_DIR (the server's reports_dir) in DRSM's etc/hosts/_defaults.conf. If DRSM runs on another machine, sync the reports to it.
  2. Make a host file for every agent report: utils/lra_hosts.sh (dry run, then --apply).
  3. For the OpenSCAP HTML links on the Vulnerabilities page, set $LRAreportsDir in the dashboard's config/drsm.php where the uploads land.

The linux plugins

PluginChecks
linux/checkinReport age, agent version, host facts
linux/resourcesCPU, load, memory, swap, disks, inodes, network, with the same metrics as the SSH plugins so trends work
linux/updatesPending updates, days since the last update, restart needed
linux/securitySELinux, firewall, auditd, sshd, failed units
linux/vulnerabilitiesAn error for critical advisories, a warning for important ones, critical CVEs with no fix yet, an old or failed scan, a low compliance score
linux/hooksEvery report hook; a plugin with LRA_HOOK=<name> shows one hook as its own check

Each plugin's settings can be changed per host in its host file, for example linux_vulnerabilities_WARN_SEVERITY=Critical.
